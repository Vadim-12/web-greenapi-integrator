# Telegram messenger — тестовое задание

Проект создан официальным шаблоном `npm create vite@latest -- --template react-ts`.

## Запуск

```bash
npm install
npm run dev
```

Проверка production-сборки:

```bash
npm run build
```

## Возможности

- React + TypeScript + Vite;
- переключатель Telegram / WhatsApp / MAX с отдельными чатами, историей и ключами каждого инстанса;
- отдельная тёмная визуальная тема для каждого мессенджера;
- демо-режим без ключей;
- подключение к GREEN-API для выбранной платформы;
- отправка через `sendMessage`;
- получение через длинный опрос `receiveNotification` с подтверждением через `deleteNotification`.
- индикатор набора текста через `sendTyping` (не чаще одного запроса в 1,5 секунды).

Токен вводится только в память текущей вкладки и не сохраняется. Для реальной проверки нужен существующий Telegram-аккаунт, авторизованный в инстансе GREEN-API. В production вызовы GREEN-API следует перенести в серверную прослойку, чтобы токен не попадал в браузер пользователя.

## Структура

Проект следует упрощённому FSD-подходу — без излишней вложенности для небольшого тестового:

```text
src/
  app/                         # только точка входа и композиция страницы
  pages/messenger/model/        # orchestration: useMessenger, состояние и сценарии
  pages/messenger/ui/           # композиция виджетов страницы
  widgets/                      # независимые крупные блоки: sidebar, диалог
  entities/chat/{model,ui}/    # сущность чата: типы, чистые функции, UI
  entities/message/{model,ui}/ # сущность сообщения
  features/                    # пользовательские сценарии: подключение, отправка,
                               # создание чата, long polling
  shared/api/green-api/        # изолированный HTTP-клиент GREEN-API
  shared/lib/                  # низкоуровневые утилиты: ID, время, URL, HTTP
```

В демо-чатах отправка имитируется локально: сообщения не покидают браузер и через короткую задержку получают две галочки. Для настоящего чата нужно подключить API выбранного мессенджера и создать чат с реальным `chatId`.

Одна галочка у исходящего сообщения означает, что GREEN-API принял его в очередь. Она не является подтверждением доставки адресату: такой статус потребовал бы отдельной обработки webhook-уведомлений о доставке.

## Проверки

```bash
npm test       # unit- и integration-тесты (Vitest)
npm run test:e2e # e2e в Chromium (Playwright)
npm run test:all # все тесты одной командой
npm run lint
npm run build
```

Unit-тесты покрывают чистые модели чатов и сообщений, API-клиент, утилиты,
конфигурацию платформ и изолированные UI-компоненты. Интеграционный тест
проверяет изоляцию состояния Telegram / WhatsApp / MAX на уровне страницы.
E2E-тест воспроизводит сценарий пользователя в браузере: переключение платформ
и создание чата. Реальные запросы к GREEN-API не выполняются автоматически:
для них требуются персональные ключи, поэтому HTTP-граница проверяется через
мок `fetch`.
